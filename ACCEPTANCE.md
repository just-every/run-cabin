Statuses mirror the authoritative current Status rows and definitions in the contract. A done entry is a narrow implemented behavior with an exercising test; partial entries identify exactly what exists. Missing entries are build work, not skipped acceptance. All journeys must run through the real app, documented API, shared CLI or provider boundary with permissioned data; network/paid-edge test doubles do not establish production provider acceptance. Do not enable real guest sends, charges, access changes, filings or payouts without the explicitly authorized integration and human controls.

For browser journeys use realistic US properties, guests, owners and USD amounts at 1440 and 390 pixels; test property-local time zones, permitted roles and failure recovery. Native journeys require both iOS and Android. Report only actually observed outcomes; provider submission, acknowledgment, delivery, physical readiness and final financial closure are separate evidence.
