# Saved reports and scheduled sharing

Reports can save the current REPORT-001 filters, then explicitly authorize a schedule. Saved definitions use the same validated dates, home, owner reference, channel, cash/accrual basis and stay/booking basis as live reports. Saving a definition does not send anything. A schedule retains the exact saved revision and filters; later definition edits never silently change an approved schedule.

Every schedule displays its reporting period, one recipient, CSV or JSON format, cadence and next UTC run instant. Create separate schedules for multiple recipients so each has its own scoped artifact and outcome. Periods are the saved date window, the previous complete UTC calendar month, or the previous complete Monday–Sunday week; the resulting dates are interpreted in each home's local zone under REPORT-001. Weekly and monthly cadence advance from the scheduled occurrence, rather than the processing time. Each occurrence is claimed once. A once-only schedule stops after its claim. Monthly dates beyond the next month's last day clamp to that day.

Only human report managers with finance/report access can save or schedule. A team recipient must be an existing active manager with active sign-in access and permission for every selected home. A restricted manager can schedule only their own saved definitions within their current property/action scope. The installation owner manages rental-owner recipients. Rental-owner recipients must be a current property's owner email, or a co-owner in the current dated management agreement with an explicit active rental-owner team grant for that home and owner reads. Historical statements, former agreements and a typed arbitrary email do not establish current report access. Co-owned stays retain occupancy but withhold full contract and host-payout amounts: each recipient receives only their own posted allocation journals; unallocated ADR amounts are explicitly unavailable.

At run time, Cabin rebuilds native member authority, compares the approved grants, checks current property interests and applies the recipient's scope to report generation. A changed scope or lost owner interest refuses the run. New portfolio homes also require a fresh review rather than silently expanding a saved report. Rental-owner generation uses the owner-specific REPORT-001 reader; another owner's journals, performance or unallocated full co-owner amounts cannot enter the artifact. Source links use the permitted owner portal. A retained former-owner ledger reference does not itself authorize delivery.

Each run records its due time, period, resolved filters, exact report revision and generation cutoff, resolved access scope, frozen artifact SHA-256, delivery history and provider acceptance reference when available. CSV/JSON bytes are stored durably and downloaded without regeneration or truncation. Mail sends a sign-in-protected link to those bytes. Opening a link rechecks current creator and recipient grants; possessing the URL grants no access. Native manager artifacts use `/api/cabin/report-artifacts/:runId`; owner artifacts use `/owners/reports/:runId`. The response must retain private/no-store headers and use the stored filename and content type.

Changed authority, generation errors, unavailable mail and failed or uncertain delivery create an assigned follow-up and pause subsequent sharing. The active report manager is responsible; when their access is lost, the installation owner receives responsibility. Interrupted generation or sending is assigned after fifteen minutes, without automatic resend. Resolution records who checked it and their explanation; it does not resend or reactivate anything. Create a newly reviewed schedule when appropriate. Provider sharing and privacy contact restrictions are rechecked at the mail boundary. Development suppression is recorded as suppression, never delivery success.

## Integration

`reportSharingCommand(context, name, input)` handles `report.save`, `report.schedule`, `report.pause` and `report.followup.resolve` inside the normal guarded domain transaction. `reportSharingState(db, actor)` supplies the manager view. `runReportSchedules(env)` runs from normal settlement/Cron. `downloadReportArtifact(db, actor, runId)` and `downloadOwnerReportArtifact(db, email, runId)` return `{content, contentType, filename, sha256}`. Owner email must come from the existing owner session. `ownerReportArtifacts(db, email)` lists currently permitted frozen reports for the owner portal.

`report.schedule` takes `savedReportId`, `savedReportRevision`, `recipientKind` (`owner` or `member`), `recipientEmail` or `recipientMemberId`, `period` (`saved-window`, `previous-month`, `previous-week`), `cadence` (`once`, `weekly`, `monthly`), `format` (`csv`, `json`), `nextRunAt` and explicit `consent: true`. `report.save` takes `name` and either a `filters` object or the existing direct report query fields. Update/pause/resolve commands require the exact displayed revision.
